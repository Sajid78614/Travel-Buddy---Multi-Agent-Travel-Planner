# ✈️ TripGraph: Multi-Agent Travel Planner

A LangGraph-powered multi-agent travel planning system that generates personalized travel itineraries by coordinating specialized AI agents for flights, hotels, weather, and itinerary planning.

The project demonstrates two different architectures:

- **Main Branch** – Direct API integration approach.
- **feature/mcp-integration Branch** – MCP (Model Context Protocol) based architecture using remote and local MCP servers.

---

# Features

- Multi-agent workflow using LangGraph
- Flight recommendations
- Hotel recommendations
- Current weather and weather forecast
- AI-generated travel itinerary
- PostgreSQL checkpointing for persistent graph state
- Groq LLM integration (Llama 3.3 70B)

# Project Evolution

## Phase 1 — Direct API Integration (`main` branch)

The initial implementation integrates external services directly into the LangGraph workflow without MCP.

### Flight Agent

Uses the AviationStack API to retrieve:

- Airport information
- Airline information

The collected data is passed to the LLM to generate flight recommendations.

### Hotel Agent

Uses the Tavily Search API to search for:

- Hotels
- Accommodations
- Nearby places

### Weather Agent

Uses the OpenWeather API for:

- Current weather
- Weather forecast

### Itinerary Agent

Combines outputs from all previous agents and generates the final travel itinerary.

# Phase 2 — MCP Integration (`feature/mcp-integration` branch)

## Why Switch to MCP?

The initial implementation successfully integrated external APIs directly into each agent. While this approach worked well for a proof of concept, it introduced tight coupling between the agent logic and the underlying API implementations.

For example:

- The Flight Agent directly interacted with the AviationStack API.
- The Hotel Agent directly queried the Tavily Search API.
- The Weather Agent directly called the OpenWeather API.

As the project grew, this architecture presented several challenges:

- Agents became dependent on specific API implementations.
- Replacing or upgrading an API required modifying agent logic.
- Integrating additional tools increased code complexity.
- Tool discovery and reuse across agents became difficult.
- The system was less modular and harder to extend.

The second phase migrates the application to **Model Context Protocol (MCP)**.

Instead of calling external APIs directly, each agent communicates with MCP tools exposed by remote or local MCP servers.

This makes the architecture modular, reusable, and easier to extend.

# MCP Architecture

## Remote MCP Server

### Tavily MCP

Used for hotel search and travel-related web search.

```
Hotel Agent
      │
      ▼
Remote Tavily MCP Server
      │
      ▼
Tavily Search Tool
```

---

## Local MCP Server

### AviationStack MCP

A local MCP server exposes aviation-related tools such as:

- list_airports
- list_airlines

The Flight Agent invokes these tools through MCP instead of calling the API directly.

```
Flight Agent
      │
      ▼
Local AviationStack MCP Server
      │
      ▼
list_airports
list_airlines
```

---

## Custom MCP Server

### OpenWeather MCP Server

A custom MCP server was developed for weather services.

Available tools:

- get_current_weather
- get_forecast

The Weather Agent uses these MCP tools for weather information.

```
Weather Agent
      │
      ▼
Custom Weather MCP Server
      │
      ▼
Current Weather
Forecast
```

# LangGraph Workflow

The application uses a sequential LangGraph workflow.

```
START
  │
  ▼
Flight Agent
  │
  ▼
Hotel Agent
  │
  ▼
Weather Agent
  │
  ▼
Itinerary Agent
  │
  ▼
END
```

Each agent updates a shared `TravelState`, allowing downstream agents to use outputs generated by previous agents.

---

# Checkpointing

The workflow uses PostgreSQL with LangGraph's `PostgresSaver`.

Benefits:

- Persistent conversation state
- Recoverable executions
- Thread-based session memory
- Workflow resumption

# Running the Project

## Clone

```bash
git clone https://github.com/rishav-RG/TripGraph-Multi-Agent-Travel-Planner.git
cd TripGraph-Multi-Agent-Travel-Planner
```

---

## Create Virtual Environment

```bash
python -m venv venv
```

Activate:

Windows

```bash
venv\Scripts\activate
```

---

## Install Dependencies

```bash
pip install -r requirements.txt
```

---

## Configure Environment Variables

Create a `.env` file.

```text
GROQ_API_KEY=
GROQ_MODEL=openai/gpt-oss-120b

TAVILY_API_KEY=

AVIATION_STACK_API_KEY=

OPENWEATHER_API_KEY=

DATABASE_URL=
```

`GROQ_MODEL` is optional; it defaults to `openai/gpt-oss-120b`. Set it to a
chat model available to your Groq account if you want to use a different model.

---

## Run the Application

### Option 1 — Command Line Interface

```bash
python main.py
```

Example:

```
Enter travel request:

Plan a 5 day trip to Japan.
```
